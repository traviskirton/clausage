# Clausage (formerly Claude Usage; claude-menubar)

macOS menubar app showing Claude plan usage limits, plus a Notification Center widget. SwiftUI, Xcode project generated by XcodeGen. App `Clausage.app`, bundle ID `com.postfl.clausage` (renamed from `Claude Usage.app` / `com.postfl.claude-usage` in 0.0.4), team JABT Labs Inc. (`G3GED29J33`), sandboxed.

## Layout

- `App/` app code (menubar, popover, settings, notifications, sessions, Sparkle updater)
- `Shared/` code shared by every target, Mac and iOS (models, forecast and display rules, app-group store, `UsageClient`, weekly history + chart model, brand: `Brand.swift` fonts/mark/wordmark/tally, `Brand.xcassets` color tokens, `Fonts/` Bricolage Grotesque Bold, OFL)
- `SharedUI/` SwiftUI views shared by the iOS app, iOS widgets and macOS widget (rows, bars, running-total chart, widget content)
- `Widget/` macOS WidgetKit extension (uses `SharedUI`)
- `iOS/` iPhone app (`iOS/App`), its widgets (`iOS/Widget`: small/medium/large, Lock Screen gauge + inline) and code both use (`iOS/Shared`). Bundle ID `com.postfl.clausage-ios`. Standalone: nothing syncs from the Mac
- `Tests/` `ClausageTests` unit tests (history/chart states 6a–6f, parsing, Claude Code breakdown port): `xcodebuild -project Clausage.xcodeproj -scheme ClausageTests -derivedDataPath build-dbg test`
- `Resources/` asset catalog (app icon, generated by `tools/make-icon.swift`)
- `project.yml` source of truth for the Xcode project (`Clausage.xcodeproj` is generated, not committed)
- `build.sh` dev build/install, `release.sh` notarize + publish
- Local only (gitignored): `research/`, `design/` (except `design/clausage-icon.icon`, the app icon the build uses), `dev-reports/` (milestone reports are written there but not committed), `.claude/release.md`, `.claude/release.env`

## Daily dev

1. Edit code, then `./build.sh install` (builds, replaces `/Applications/Clausage.app`, relaunches).
2. `Clausage --reset` (run the binary with `--reset`) behaves like a first launch: forgets accounts, consent, login item.
3. Commit after each working change (stage explicit paths; `.vscode/` stays untracked).
4. Ask before replacing the user's installed copy with a dev build if they may be relying on it.
5. iOS: `xcodebuild -project Clausage.xcodeproj -scheme ClausageiOS -sdk iphonesimulator -derivedDataPath build-ios -destination 'id=<sim>' build`, then `xcrun simctl install`. Debug-only launch args: `--render-gallery <dir>` (PNGs of every widget family, dark/light/tinted), `--self-test <file>` (checks the Keychain group and App Group entitlements), `--demo` (fixture data, no network), `--demo-bottom`, `--demo-open settings|privacy|feedback`, `--demo-welcome`.
6. Mac debug build: `build-dbg/.../Clausage --render-gallery <dir>` (dir inside `~/Library/Containers/com.postfl.clausage/Data/`, the app is sandboxed) renders the popover, menu bar icon states and Settings panes; `--demo` runs on fixtures.
7. In this shell `cp` is interactive; use `command cp -f`.

## Branching and releases

- `main` = what has shipped. Every release is tagged `release-<version>` (snapshot tags `v<n>-<name>` are separate).
- Work on a branch named for the next version (`0.0.2`). Commit freely there.
- To ship, from that branch:
  1. Get the user's explicit OK. Releases put a zip and `appcast.xml` on a public host.
  2. `./release.sh <version>` (opens a new shell if needed so `SPARKLE_KEY_FILE` is set). It bumps `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION`, archives, signs with Developer ID, notarizes via Xcode's Apple login, zips, signs the appcast, uploads over FTPS, and verifies the public URLs.
  3. The script commits the `project.yml` bump and tags `release-<version>`. Then fast-forward `main` to the branch.
  4. Write a dev report if it was a milestone (local only: `dev-reports/` is gitignored, so skip the commit and hash-stamp steps).
  5. Create the next branch (`<next version>`) and, in its first commit, set `MARKETING_VERSION` in `project.yml` to that version. Leave `CURRENT_PROJECT_VERSION` alone (`release.sh` adds 1). Dev builds must always show the version being worked on.
- Hotfix: branch from the release tag, fix, ship the next number.
- Sparkle compares the **build number**, not the version; it must increase every release (the script does this).

## Release infrastructure

- Feed: `https://clausage.ai/updates/appcast.xml`. Public key is in `project.yml`; never commit or print the private key.
- Legacy feed: `https://updates.postfl.com/claude-usage/appcast.xml`. Copies shipped as "Claude Usage" (0.0.1–0.0.3) only check this URL, so `release.sh` uploads the same appcast there too. Keep it alive. Sparkle installs the update at their old path (`Claude Usage.app`) and their sandbox data doesn't carry over (new bundle ID), so they sign in again.
- Website: `site/` (plain pages for `https://clausage.ai`, linked from About), uploaded by `./deploy-site.sh`. Pre-rename release zips live in `release-legacy/` (gitignored).
- Upload host, FTP account, Keychain service names and key locations are in `.claude/release.md`, and `release.sh` reads them from `.claude/release.env`. Both are gitignored and live only on the release Mac: @.claude/release.md

## Data sources

- Usage comes from claude.ai after the user signs in inside the app (isolated `WKWebsiteDataStore` per account). Endpoint `/api/organizations/<id>/usage` is undocumented; `UsageClient.parse` accepts a `limits` array or `five_hour`/`seven_day*` keys.
- iPhone: the user signs in inside the app (`WKWebView`); the `sessionKey` cookie, user agent and org go to the Keychain group `G3GED29J33.com.postfl.clausage-ios.shared`. Refreshes are a plain `URLSession` call with that cookie (`CookieTransport`), written to App Group `group.com.postfl.clausage`. Widgets only read the App Group, except the large widget's refresh button (`RefreshUsageIntent`). Background refresh is `BGAppRefreshTask`, best effort.
- Claude Code tab reads `~/.claude/projects/*/*.jsonl` through a security-scoped folder grant the user chooses.
- Outage alerts poll `https://status.claude.com/api/v2/summary.json`.

## Gotchas

- Menubar-only app: any window needs `AppActivation.push()/pop()` or it can't be reached with Cmd-Tab.
- The "Login Item Added" banner shows the file name (`Clausage.app`); macOS controls that text.
- Dev and release builds share a bundle ID, so `./build.sh install` overwrites the notarized copy. (Idea: a separate "Clausage Dev" bundle ID.)
- Auto-update checks are off by default (`SUEnableAutomaticChecks` false).
- The widget and notifications only work from a properly signed app in `/Applications`.
